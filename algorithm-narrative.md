Enhancement and Skills Demonstrated:
	For the enhancement I created a separate file called animal_merge_sort.py and implemented a merge sort. The algorithm processes a list of dictionaries representing animal records. Accepting a sorting field and a choice to view it in descending or ascending order. Users can sort the records by age, name, or breed.
	The implementation handles numbers and text values differently. Age values are compared numerically, while names and breeds are compared without paying attention toward capitalization. Missing or incorrect values are placed at the end of the result no matter the sorting direction. When two records have equal sorting values the original order is kept. The function also returns a sorted copy instead of changing the input list to help control issues that could crop up. 
	I added the algorithm into the dashboard using a dropdown for choosing the sorting field and buttons for choosing the sorting direction. The dashboard callback retrieves records that match the active rescue filter, removes the MongoDB ObjectId field, and passes the rest of the records into the merge sort function. The sorted records are returned to the table. When results are available the dashboard would return to the first page and select the first record. 
	Keeping the selected rescue category was important. Changing the sorting field should continue to show animal records from the category a user would choose. I used a Dash store to keep that category even when a callback updates. This let the filtering and sorting options working together without having the user reselect what they had already picked. 
Algorithm Selection and Design Reasons:
	I chose the merge sort because it gives a O(n log n) ren time which scales more effectively than O(n^2) from bubble sort. Merge sort divides the input into smaller lists, sorts the smallest objects, and then merges them. The main tradeoff would be extra memory is needed during the merging. It uses O(n) temporary auxiliary memory with a O(log n) recursion stack. This tradeoff is still good as it is a consistent performance even if the number of records increases. Using a list of dictionaries also let the algorithm work directly with the animal records retrieved from MongoDB. Each dictionary keeps an animal’s fields together while the list figures out the order the records will appear in. 
	I chode to write a merge sort so I could show that I understood that an algorithm splits records into smaller elements and merges them in order. Python already has a built-in sorting function called sorted(). It is efficient, keeps equal values in the original order, and returns to a new list. I would choose the built-in function because it would be easier to maintain and use. However, writing the merge sort was useful for the enhancement as it showed off and tested my knowledge and skill of the algorithm. My performance comparison showed that merge sort was more useful in this case than bubble sort but it didn’t show that it was better than Python’s sorting. 
	Merge sorts keep records with equal sorting value in the original order. The left_first() function uses <= for ascending and >= for descending. Both comparisons choose the record from the left list when the values are equal. The function checks for missing and invalid values before doing the sorting direction. Keeping the records at the end in both orders. When both values are invalid the left record is chosen so the original order is kept.

Before measuring the performances, I would check that both algorithms have the same ordered records. It would then measure each algorithm five times and display the median time.
